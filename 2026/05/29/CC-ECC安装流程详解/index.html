CC+ECC安装流程详解

Luo Lanan Lv1
  2026-05-29 22:45:36 2026-05-29 22:45:36 Created   2026-05-30 21:29:27 2026-05-30 21:29:27 Updated  
  • AI, Claude Code 
 

最近抖音上刷到了一个从零开始教小白用Claude code写代码的短视频(其实并不短，有三十分钟).笔者也突然兴起，研究了一下Claude Code的使用方法，于是今天给大家带来一个安装Claude Code(以下简称CC), 并使用CC-Switch外接大模型，在VS Code使用的详细教程. 顺带分享一下笔者自己踩坑的心路历程

一、安装CC

安装所需环境: Node.js && Git

首先，在进行CC的安装之前，我们需要与先准备环境。这里我们需要下载Node.js 和 git。这里我推荐大家到官网去下载：

Node.js: https://nodejs.org/zh-cn
git: https://git-scm.com/install/windows

到这里，你就可以输入claude来激情使用你的CC了！

二、安装CC-Switch并接入其他大模型(以DeepSeek为例)

安装CC-Switch

安装好CC之后呢，我们需要到github上去安装一个叫做CC-Switch的软件，这个软件可以帮助我们便捷的管理CC和其他外接的大模型。

CC-Switch: https://github.com/farion1231/cc-switch/releases

打开CC-Switch之后呢，选择Claude，这就是我们管理Claude的界面了。目前里面只有Claude Official一个模型。接下来我们给CC加入外接的模型。

使用CC-Switch外接DeepSeek

这里笔者选择使用DeepSeek v4 Pro来举例。首先呢，我们来到DeepSeek的开放平台。你可以选择注册或者使用已有账号登录。

登陆之后呢，我们首先要来做一下充值，不用太贵。如果你只是想试试deepseek的味道，那么充值十元对你来说绰绰有余。充值完成之后呢，我们点击左侧的API keys来给自己创建一个api。

我们新建一个API key，你可以给他起一个名字，比如笔者这里选择就叫他Claude Code。创建好之后，我们会看到一串以sk-开头的神秘字符串，这就是你的API key了，把他保存好，并且保证这个神秘字符串没有计划之外的人知道。当你关闭这个小弹窗之后，你就再也见不到这串神秘的字符串了，所以一定一定要把他保存好，所有拥有这个API key的人，都可以直接使用你账户里的余额token，所以不要把他告诉你不信任的人。

接下来我们回到CC-Switch，在CC的配置页面点击右上角的加号，选择DeepSeek，进入配置页。当然这里还有许多其他的AI大模型，大家可以根据自己的需求去添加。

在API key一栏填入我们刚才得到的神秘字符串。然后将模型映射的主模型和Opus模型都改成deepseek-v4-pro[1m]。其余的改成deepseek-v4-flash。并且在json配置中打开最大强度思考后，就可以点击添加了。

添加完成后，我们可以点击这个大模型右侧的小试管图标来检测一下链接。如果正常运行了，那就说明我们已经成功为CC接入了DeepSeek。

三、在VS Code中使用CC

安装VSCode以及插件

我们这里进入VS Code的官网并且下载好对应的版本：

VS Code: https://code.visualstudio.com/

下载好之后，我们打开VS Code，点击左侧一个像windows一样的图标，进入插件市场。进入之后搜索Claude Code for VS Code，下载带有官方认证的版本。

到这里我们一切准备的工已完毕，打开一个项目或者普通的文件夹，你就通过右上角或者侧栏的图标来使用Claude Code了！

四、为CC添加ECC

CC在使用过程中，最不可缺少的就是各种各样的skill。那么这里笔者推荐大家搭配使用的skill就是Everything Claude Code。

Everything Claude Code(ECC)是来自 Anthropic 黑客马拉松获胜者的完整 Claude Code 配置集合。 不止是配置文件，而是一整套完整系统：技能体系、本能行为、记忆优化、持续学习、安全扫描，以及研究优先的开发模式。

ECC的官方文档给出了许多不同的安装方式，但在这里笔者推荐大家以plugin的方式去安装ECC。因为作为plugin1的ECC可以应用于全局，而非单个项目，这会更加的便捷。

笔者当时十分疑惑，并未理解到这与git有什么关系，只以为是claude抽风。开始在网上寻找类似的处境以及解决方法。但遗憾的是，未曾有类似的帖子出现在互联网上，于是笔者开始测试自己的claude。

但经过初步的排查，一个新装好的CC不可能在配置上有任何问题，而且网上的安装过程也并没有提到任何额外的配置。于是笔者确信了：claude是没有问题的，那么问题就出在git上了。而此时笔者又想起了在曾经，某一个遥远的下午，指点笔者的学长曾问：“你这台电脑上真的有git吗？”

笔者略加思索，终于回忆起自己在初入计算机世界时，为了保留C盘的内存，将git的安装位置装在了D盘。

多年前一个少年的灵机一动，竟给自己留下了如此之大的坑去填。笔者写到这里不禁要问：“你这家伙……究竟看到了多远？”

在笔者重新为自己的电脑安装了一个更新的git之后，这个问题就迎刃而解了。

安装好了全套工具之后，笔者也是美美的使用上了CC……吗？

笔者十分震惊：自己未曾做过任何更改，难道仅一夜之差，claude自己就给自己填了个bug么？

事实果真如此：在2026-05-29当天的凌晨，Claude Code 自动更新到了 v2.1.154（构建时间 2026-05-28，就是前一天），新版本改变了 system prompt 的发送格式——把它放在了 messages 数组里作为 system 角色，而 DeepSeek API 不接受这种格式。

看到这其实笔者已经有些力竭，改了一晚上的环境，装了一晚上的配置。第二天凌晨你就给我封杀了么？

写在结尾：其实这篇blog本来应该是有图的，但笔者实在太懒，就省了。CC本质上是一个不错的工具，但使用多有不便，这套组合下来不仅可以改变我们的使用环境，更方便对cc和token的管理，安装方式也多有四处借鉴，笔者只是在此总结各种实操的做法以及会出现的问题。
另：没人觉得让AI喊自己先生很爽么？真的很有那种仪式感与活人感，听到AI祝我一切顺利、工作愉快，确有那种小助理的感觉了。
